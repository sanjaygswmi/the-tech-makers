# Content Strategy & Service Documentation

This folder consolidates the former `ai-docs/` documents under the main `docs/` documentation tree. The original material has been preserved; the category/tag guide formerly misnamed `tasks.md` has been renamed to describe its actual contents.

## Documents

- [Service page development plan](./service-page-development-plan.md) — service route/content audit, related-blog association requirements, UX/accessibility opportunities, and implementation sequencing.
- [Blog inventory review workflow](./blog-inventory-review-workflow.md) — evidence-based CMS export and article-by-article review process before remapping, refreshing, consolidating, or retiring posts.
- [Existing blog-to-service mapping audit](./existing-blog-service-mapping-audit.md) — provisional first-pass review of publicly visible homepage blog cards; not a substitute for a complete CMS inventory.
- [Service blog content calendar](./service-blog-content-calendar.md) — proposed topics and publishing cadence, subject to archive-overlap and search-demand checks.
- [First four service blog briefs](./first-four-service-blog-briefs.md) — draft briefs for editorial review; these are not published articles.
- [Admin Category & Tag implementation guide](./ADMIN-CATEGORY-TAG-IMPLEMENTATION-GUIDE.md) — implementation guidance for category and tag management in the admin panel.

## How this relates to the main revamp plan

Use the parent [site-revamp README](../README.md) as the entry point and [task tracker](../TASKS.md) for current status and sequencing. This folder contains supporting research and implementation briefs; a proposal in a document does not mean the corresponding feature or content has shipped.

## Editorial and implementation safeguards

- Review the full article body and CMS data before making bulk blog-to-service assignments.
- Preserve existing URLs and canonical behavior unless a separate SEO review approves a change.
- Do not publish draft briefs as finished articles without fact-checking, overlap review, and editorial approval.
- Do not claim a feature is implemented or validated based on planning documentation alone.
