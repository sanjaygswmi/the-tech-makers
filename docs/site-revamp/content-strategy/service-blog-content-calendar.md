# Service Blog Content Calendar

**Repository:** `the-tech-makers/the-tech-makers`  
**Working branch:** `audit/site-revamp-plan`  
**Status:** Editorial plan for review; no production publishing or deployment.

## Purpose

Build a useful, sustainable content pipeline for the 12 current service pages. Each article should answer a real buyer question, demonstrate practical expertise, and link readers to the most relevant service page. The calendar is a proposed backlog, not a claim that these topics have already been researched or published.

## Editorial rules

1. **One primary service per article.** Assign one main service association and add secondary services only when the article genuinely supports them.
2. **Categories describe topics; service associations control placement.** Use category-to-service mappings as editor suggestions, not automatic publishing rules.
3. **Use search intent, not keyword stuffing.** Write for buyers evaluating options, scope, cost drivers, risks, and implementation.
4. **Make claims verifiable.** Do not invent client results, benchmarks, certifications, or guarantees. Use screenshots, code examples, checklists, diagrams, and real project lessons where available.
5. **Every article has a next step.** Link to its primary service page in context and include a relevant, low-friction enquiry CTA.
6. **Avoid duplicate intent.** Before drafting, search the existing blog archive for a similar title/topic and update a useful existing article instead of creating a near-duplicate.
7. **Refresh deliberately.** Review technical guides when tools/platforms change; show updated dates only when content has materially changed.

## Internal-linking guidance

- Link to the primary service page within the first few useful sections when context allows; avoid forced links in the opening sentence.
- Link to a second service only when it is a genuine adjacent step. For example, a technical SEO launch checklist may also link to Web Development.
- Add links from the service page to its latest 3–4 explicitly associated posts; use descriptive titles rather than generic “click here”.
- Where relevant, add reciprocal links from an article to its primary service page. Do not require every article to link to every service.
- Link between related articles when one naturally answers the next question in the reader journey.
- Keep the global category archive useful for discovery, but do not rely on category alone to decide which service page displays a post.

## Existing-article audit and assignment workflow

Before backfilling existing posts, export or inspect the blog archive and record:

| Field | Action |
|---|---|
| Existing URL/title | Preserve URL and canonical unless a separate redirect decision is approved |
| Current category/tags | Normalize duplicates and correct obvious misclassification |
| Recommended primary service | Assign only after reading the article, not from title alone |
| Secondary services | Optional; use sparingly |
| Content quality | Keep, update, consolidate, or retire after review |
| Next action | Map now, revise first, consolidate, or leave unassigned |

**Do not bulk-assign every post from a category without editorial review.** Some existing categories, such as e-commerce development, WooCommerce, payment gateway integration, and branding, can relate to multiple services depending on the actual article. The category mapping should provide a starting suggestion only.

## Success measures

Review monthly:
- Number of service pages with at least three genuinely relevant articles.
- Number of published articles with a primary service association and a clear service-page link.
- Organic impressions/clicks for article and service-page query groups, where Search Console data is available.
- Relevant enquiry clicks or assisted conversions from article pages, where analytics is configured.
- Content freshness: articles reviewed after meaningful product, platform, or process changes.
- Editorial quality: avoid using publication count alone as the success metric.

## Recommended next implementation step

Create an inventory of existing published blogs with title, URL, categories, tags, and content summary. Use it to map appropriate existing articles to services and identify overlaps before writing new posts. Then prioritize the first four briefs above based on the real archive and available subject-matter expertise.
