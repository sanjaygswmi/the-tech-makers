# Keyword Landing Pages and USA Local SEO Plan

**Website:** https://www.thetechmakers.com  
**Market priority:** United States, with city-level intent where commercially relevant  
**Status:** Scope approved for audit/planning; keyword inventory and page creation are not yet complete  
**Design constraint:** preserve the current visual design and existing brand system

## 1. Objectives

1. Audit all homepage tags, labels, service names, linked topics, and keyword-bearing content.
2. Map each meaningful keyword/search intent to the most relevant existing page or a proposed dedicated landing page.
3. Improve visibility for relevant US searches, including city-specific searches where The Tech Makers can genuinely serve those customers.
4. Turn relevant organic visits into qualified enquiries with clear paths to contact.
5. Avoid fabricated local presence, unsupported claims, and low-value search pages.

## 2. Homepage keyword/tag inventory

Review the homepage and all sections it composes, including:
- hero/banner text, headings, subheadings, CTAs, and navigation;
- service names, solution labels, industry labels, and any visible tags/chips;
- review/testimonial labels, blog/category tags, portfolio/project links, and footer links;
- image alt text and internal-link anchor text where they accurately describe the content.

For every observed item, record:
- exact text and source component/route;
- whether it is a visible tag, service/topic, CTA, internal link, or metadata term;
- likely search intent and audience;
- current destination (if any);
- keyword cluster / primary phrase and useful variants;
- existing page that already satisfies the intent;
- proposed action: keep, improve existing page, create landing page, merge into another cluster, or exclude;
- priority, factual/content dependencies, and verification status.

Do not treat every word or navigation label as a separate target keyword. Inventory all relevant tags/terms first, then cluster by **distinct search intent**.

## 3. Landing-page policy

Create a dedicated landing page for every approved keyword cluster that represents a distinct service, solution, industry, or other commercially meaningful search intent and does not already have a suitable page.

- Each approved cluster should have one primary URL and one clearly assigned target intent.
- If the user's instruction is interpreted literally as one page per tag, still first map synonyms and overlapping tags; do not publish multiple pages that compete for the same query intent.
- Reuse the existing site's layout and design system. This is content, information architecture, and functionality work—not a new visual redesign.
- Each page must contain genuinely useful, specific information: what is offered, who it is for, outcomes/process where supportable, relevant proof only when verified, FAQs where useful, and a clear enquiry CTA.
- Write unique title, meta description, H1, introductory copy, page body, internal links, and CTA context. Shared templates are fine; duplicated copy with only a keyword swapped is not.
- Add relevant pages to navigation, service/topic hubs, breadcrumbs, contextual links, and XML sitemap where appropriate.
- Define canonical URLs and avoid accidental duplicate routes, query-parameter duplicates, and overlapping pages.
- Do not invent client names, certifications, reviews, results, guarantees, or technical capabilities. Mark facts needing owner confirmation.
- If a tag has no distinct intent, insufficient business relevance, or cannot support a useful page, document why it is merged, improved in-place, or excluded rather than creating a thin page.

## 4. USA and city-level local SEO

### Market and city selection

- Prioritize the United States as the main target market.
- Build a candidate city list from actual business priorities, service fit, Search Console query data (if available), existing leads/customers, and realistic delivery capability.
- Do not generate pages for every US city by default. Rank candidate cities by evidence and commercial relevance before production.
- Use city-level pages only when they can provide useful, truthful city-specific value and a distinct search intent.
- If the business serves a city remotely and has no physical office there, describe the service accurately. Never imply an office, local staff, address, or in-person coverage that does not exist.

### Local page requirements

Where a city page is justified, include accurate and distinct information such as:
- city-specific service context or customer needs supported by research;
- services actually offered to customers in that location;
- clear remote/on-site service availability and limitations;
- relevant project examples or testimonials only if genuine and approved;
- local-market FAQs and useful internal links;
- consistent business contact details and a clear lead CTA;
- unique metadata, heading structure, canonical, indexability, and sitemap inclusion when the page is intended to rank.

Do not create doorway pages: near-identical city pages whose primary purpose is to funnel users to the same generic page. Do not use false local addresses, fake local business listings, or misleading LocalBusiness structured data.

### Technical and on-page checks

- Audit title tags, meta descriptions, H1/H2 hierarchy, canonical tags, robots directives, sitemap, redirects, status codes, internal links, breadcrumbs, and Open Graph data.
- Confirm that the sitemap includes only canonical, indexable, useful pages.
- Use structured data only when the page and business facts qualify; validate it and keep it consistent with visible content.
- Review mobile usability, page performance, accessible form behavior, and lead tracking without changing the visual identity.
- Establish Search Console and analytics baselines where access is available. Separate measured data from assumptions.

## 5. Keyword-to-page mapping template

| Field | Required value |
|---|---|
| Inventory ID | Stable identifier |
| Exact tag/term | Text as found on the site |
| Source | Homepage section/component or URL |
| Intent | Service / solution / industry / local / informational / other |
| Primary keyword cluster | One distinct search intent |
| Variants/synonyms | Related terms that should not automatically become separate pages |
| Existing destination | Current URL or none |
| Recommended action | Keep / improve / create / merge / exclude |
| Proposed URL | Proposed canonical slug, if a new page is approved |
| Market/location | US-wide or a justified city |
| Unique value/content needed | Specific useful content required |
| Evidence/dependencies | Search data, business facts, owner approval |
| Priority/status | P0/P1/P2 and Not started/In progress/Blocked/Done |
| QA evidence | Content, links, metadata, indexability, tests |

## 6. Acceptance criteria

- Every relevant homepage tag/keyword is inventoried; the audit includes the actual text and source location.
- Every term is mapped to an existing page, an approved new landing page, a merged cluster, or a documented exclusion.
- Every approved keyword cluster has exactly one primary target URL unless a documented intent distinction justifies more.
- All new pages have unique, accurate content and metadata, working internal links, a relevant CTA, and correct technical SEO signals.
- US city pages are supported by real service capability and useful city-specific content; no fabricated offices or doorway pages.
- The existing visual design is preserved.
- Build, lint, automated tests, route/link checks, and applicable SEO validation results are recorded.
- Search performance is not promised; rankings and traffic must be measured after publication.

## 7. Dependencies and limits

- Search Console and analytics access for query, country, city, and conversion baselines.
- Owner confirmation of priority services, ideal US customer profiles, service-delivery model, supported cities, and factual claims.
- Search-demand research before deciding the final keyword and city list.
- No page count is assumed until the homepage inventory and keyword clustering are complete.
